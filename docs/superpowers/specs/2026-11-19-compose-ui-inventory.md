## App non-layout resource-backed UI

- `res/xml/termux_preferences.xml` and related `termux_*_preferences.xml` files are parsed by the AndroidX PreferenceFragments (`TermuxPreferencesFragment`, API/Float/Tasker/Widget fragments and debugging/terminal subfragments). These form the legacy Termux/plugin settings UI surface. The BeTermux `SettingsActivity` is separately Compose and does not itself invoke those fragments in the inspected activity source. Classify the preference-fragment host/UI as system/platform UI pending explicit product scope; do not silently migrate or remove plugin preference contracts.
- `res/menu` resources are native ActionBar menus for `ReportActivity` and `TextIOActivity` in termux-shared, not app-owned screen menus.
- Drawables, colors, styles, themes, ids and provider path XML support active screens but are not standalone UI surfaces.

## Manifest-owned destinations and system surfaces

Manifest-registered BeTermux destinations: launcher `TermuxActivity`, `HelpActivity`, `SettingsActivity`, `PackageManagerActivity`, `SshManagerActivity`, `FileManagerActivity`, `DevBrowserActivity`, `ThemePickerActivity`, `FileReceiverActivity`, and shared `ReportActivity`. The file receiver is an external SEND/VIEW integration and uses the shared message utility; its chooser, permissions and document picker are Android platform UI. `ControlDeckPresentation` is created by `DeckBridge` for the secondary display; it is not a manifest-registered Activity, and its rendered screen is Compose. Services, receivers, providers, shortcuts, notifications, input method, document provider and package-installer/permission interfaces are not app-authored Compose screens.

## Inventory limits / verification notes

- Candidate verification was source/layout/manifest reference search, not runtime instrumentation. The four named orphan resources have no app source inflations, `R.layout` references, included-layout references or registrations.
- Programmatic views in `TermuxActivity` include tab pills, active/live markers, add-tab affordance and status/action chrome; these are grouped as the session/tab strip and main host rows above. Programmatic menus/dialogs are separately enumerated above.
- Activity dialogs produced by Android (`AlertDialog` for terminal confirmations/URL/session actions) are classified as migration targets only where BeTermux owns the dialog content/action flow; OS permission, chooser, picker and installer UI are excluded.
